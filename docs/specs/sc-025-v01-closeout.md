# SC-025 [P1][Reliability] 修复 V0.1 常驻与订阅缺陷并完成发布验收

Parent: #1

状态：待实现。测试边界已由用户确认。本规格由 2026-09-26 仓库复核结果生成，不代表相关修复或发布已经完成。

## Problem Statement

V0.1 的核心链路已实现，24 张子工单已关闭，但用户仍会遇到三个已复现的问题：切月后右栏保留原日期却丢失详情；应用跨午夜常驻后“今天”仍指向启动日期；订阅刷新解析期间删除来源，刷新继续写回无来源事件。第三项已用 260 条合成事件复现。

网络任务尚无真正的 HTTP 取消能力。现有安装包与安装验收对应 9 月 25 日旧构建，不能证明当前源码交付质量；新增图标的分发授权与参考图来源仍有待处理项。用户需要一个日期与详情一致、删除结果可靠、适合常驻且有真实发布证据的 V0.1。

## Solution

修复三个缺陷并建立行为回归，补齐订阅请求取消和失效结果隔离。保持当前 V0.1 文字与代码降级范围，完成实际分发资产审查，再从修复后的确定代码版本生成 Windows Release Candidate，并对该产物完成系统集成与常驻验收。最后据真实结果同步发布记录和父 Epic。

## User Stories

1. 作为日历用户，我希望切换月份时保留已选日期，以便继续阅读正在查看的日程。
2. 作为日历用户，我希望选中日期离开月网格后仍保留完整 Inspector，以便不会把有日程的一天误认成空白日期。
3. 作为日历用户，我希望跨月查看仍能看到农历和节假日，以便日期语义与右栏日期一致。
4. 作为球迷，我希望切月后原选中比赛的联赛、双方、开赛时间和场地仍在，以便继续核对比赛详情。
5. 作为日历用户，我希望来源开关对网格外选中日期也立即生效，以便右栏不显示已隐藏的数据。
6. 作为日历用户，我希望快速连续切月不会让晚到的结果替换当前详情，以便始终看到正确日期的数据。
7. 作为常驻用户，我希望跨午夜后今天标记自动更新，以便正确识别当前日期。
8. 作为常驻用户，我希望“回到今天”读取当前本机日期，以便从任何月份返回真正的今天。
9. 作为常驻用户，我希望跨月末、年末和闰日后日期仍正确，以便无需重启应用。
10. 作为托盘用户，我希望恢复窗口时校正今天状态，以便长时间隐藏后继续使用。
11. 作为电脑用户，我希望从休眠恢复或调整系统日期后日历重新校正，以便不沿用过期日期。
12. 作为常驻用户，我希望日期更新不强行改变正在阅读的月份或选中日期，以便当前任务不被打断。
13. 作为订阅用户，我希望删除正在下载的订阅能停止相关工作，以便不继续占用网络资源。
14. 作为订阅用户，我希望解析或标准化期间删除来源也能终止结果提交，以便删除后不留下无来源事件。
15. 作为订阅用户，我希望落库期间删除来源最终清除原始事件与增强结果，以便删除行为完整可靠。
16. 作为订阅用户，我希望删除后立即重新添加同一地址不接收旧请求结果，以便新来源只使用新操作的数据。
17. 作为订阅用户，我希望停用来源后保留缓存并停止其后台刷新，以便显示开关与已有数据保留规则一致。
18. 作为订阅用户，我希望请求取消不会被显示成普通网络失败，以便知道这是主动操作的结果。
19. 作为订阅用户，我希望取消一个来源不影响其他来源，以便其余订阅照常更新。
20. 作为订阅用户，我希望真正的网络失败继续保留旧缓存和成功时间，以便离线仍能浏览日历。
21. 作为隐私敏感用户，我希望取消与失败日志不泄露订阅凭据或事件正文，以便诊断不暴露个人数据。
22. 作为常驻用户，我希望应用保持低频调度和可响应界面，以便修复不增加空闲 CPU 或大日历卡顿。
23. 作为 Windows 用户，我希望安装包包含实际验收的修复版本，以便安装后的体验与发布说明一致。
24. 作为球迷，我希望在已安装的应用中实际收到赛前提醒，以便自动化替身之外的系统链路也有证据。
25. 作为 Windows 用户，我希望托盘隐藏、恢复、退出和单实例恢复均实际可用，以便应用长期使用时有可靠入口。
26. 作为 Windows 用户，我希望升级保留日历、设置和提醒去重状态，以便更新不会丢数据或重复弹提醒。
27. 作为 Windows 用户，我希望安装、启动与卸载都有清楚记录，以便知道哪些能力确实经过验证。
28. 作为应用使用者，我希望分发素材的来源与授权明确，以便安装包不存在未处理的素材问题。
29. 作为维护者，我希望未达到参考图的视觉明确标为已接受降级，以便组件支持图片不会被误报成默认视觉完成。
30. 作为维护者，我希望 Epic 和发布门槛与真实验收一致，以便工单关闭状态不会掩盖缺陷或未验证项。

## Implementation Decisions

- **选择日期与视图月份分离。** 月份导航保持现有选择；Inspector 按选中日期独立查询事件 occurrence 与日级语义，不依赖该日期是否属于可见网格。复用已有展开、分桶、Provider 展示载荷和来源过滤规则，业务语义继续由 Provider、Matcher 与 Metadata Resolver 负责。
- **读取结果发布保持一致。原始事件与增强结果提交都必须使 UI 读取缓存失效；原始输入版本另供增强重建检查，不能因为并发 304 或失败刷新先读到原始事件而永久保留未增强的 UI。** 日级语义与事件都对应当前选择；异步读取采用现有失效/代次思想隔离旧结果。大日历读取继续分片，不发布旧日期或半份事件集合；整理状态需可解释，不能把尚未加载误说成没有事件。
- **今天是运行期事实。** 由当前本机时钟生成日期键，跨天、窗口恢复和点击“回到今天”时校正。共享现有跨天/生命周期触发，不增加高频轮询。校正今天标记不自动切月、不强行重选；用户点击今天才同步视图月份和选择。
- **刷新操作具有独立生命周期。** 删除或取消使在途操作失效；同地址重新添加属于新操作，旧响应不能取得新来源的写入资格。网络、解析、标准化和分片落库都必须尊重失效状态，不能只在下载完成后检查一次来源存在。
- **删除与刷新提交有明确次序。** 删除返回后的最终状态不得被任何旧操作覆盖；来源、原始事件与增强结果均不存在。可复用存储接口与受控提交边界，采用操作代次/取消判据或等价方案保证这一外部契约，不强制更换存储引擎。
- **真正取消在途 HTTP。** 前端网络端口与桌面 IPC 提供关联请求的取消能力；Rust 请求处理接收取消信号并终止等待/读取。按操作标识区分并发请求，不把取消单个来源实现为全局取消。现有连接/总超时、响应体积限制与条件 GET 保留。
- **取消是独立结果。** 主动取消不推进成功刷新时间、不清空缓存、不按普通失败更新错误状态或触发失败重试。删除来源后不得恢复该来源；取消后的新刷新按现有正常调度规则处理。
- **停用与删除区别保留。** 停用不删除数据，停止该来源后续后台刷新，并使提交前的在途后台操作失效；已原子提交原始事件、进入 finalizing 的操作完成增强和落盘，停用后的事件仍被来源过滤排除。删除始终清除来源与全部事件/增强分区；显式手动刷新保持已有交互语义。关闭应用时停止调度与在途任务；隐藏到托盘继续按常驻规则运行。
- **隐私和性能边界保留。** 所有诊断延续现有脱敏出口；取消注册与监听必须清理。保留逐段分片、单次最近到期调度、同来源请求去重及刷新失败保留缓存。
- **不计划持久化 schema 变更。** 请求标识、取消状态和操作代次是运行期状态；若实现确需改 schema，需补迁移与旧快照读回验收，不能静默改变升级契约。
- **固定发布候选版本。** 三项缺陷与取消能力完成后，从确定提交生成安装包，记录代码版本、构建时间和产物校验值；后续生产代码或打包资产变化必须重新生成并复验受影响项，旧产物不能替代新版本验收。
- **资产审查先于分发验收。** 对实际打包的新增图标核对来源与分发授权并记录证据；无法确认时使用可证明来源的自有替代素材。对文档参考图补来源/授权或移除，并更新引用。这里只定义处理要求，不预先认定任何素材已经获授权。
- **维持已接受视觉范围。** 队徽、联赛 Logo、节日节气照片和球场照片不作为本次新增交付物；代码、短标签与文字 fallback 继续有效。保持照片项“部分通过/按当前范围接受”的真实描述。
- **发布结果按证据登记。** 同步 README、发布/资产/UI 验收记录及父 Epic，纳入 SC-023/024 和本规格。既有完成项不因父清单未勾选而重做；存在失败或未验收项时不得关闭 V0.1 Epic。

## Testing Decisions

测试边界已由用户确认：真实 App 操作、订阅刷新与存储、本地 HTTP 服务，以及最新 Windows 安装包实机验收。优先复用已有接口，不为测试拆出多套新业务 API。

- 测试外部行为与最终状态，不断言私有变量、调用次序或源码措辞；先把复核中的三个复现场景变为永久回归。既有 App 集成测试、订阅刷新测试与 Rust 本地 HTTP 用例提供先例。
- **App 集成：** 选中含普通事件、比赛、假期与农历的日期后跨两个月并返回，Inspector 日期和详情保持一致；覆盖重复 occurrence、来源开关、无事件日期、快速切月与读取尚未完成时改选日期。
- **假时钟与生命周期：** 覆盖普通午夜、月末、年末、闰日；推进日期、恢复窗口、点击今天，确认今天标记使用新日期，未点击今天时保留用户视图与选择；通知跨天重建继续正确。
- **订阅与真实存储：** 在下载、解析、标准化、落库的可控让出点触发删除；完成全部在途工作后来源、原始事件和增强结果仍为空，并在快照落盘与重新读取后再次确认。覆盖 260 条复现数据及 10,000 条分片数据。
- **同地址重加与并发：** 删除后重新添加同一 URL，让旧请求晚到，确认它不能覆盖新来源、新缓存或启用状态；取消一个来源不影响另一个，旧请求清理也不能注销新请求。
- **HTTP 取消：** 本地延迟响应与缓慢正文服务验证下载等待和正文读取均能主动结束，无需等到总超时；取消结果保持缓存、状态与成功时间，取消监听和请求登记无残留。保留超时、304、200、失败重试和凭据脱敏回归。
- **性能：** 用既有固定 1,000/10,000 事件工作负载复测受影响读取与刷新路径，记录任务耗时及可见/托盘隐藏空闲资源；不得取消分片或新增高频唤醒来修复日期问题。
- **Windows 产物：** 对当前 RC 实际安装、启动、升级与卸载，确认用户数据保留；操作托盘恢复/退出、单实例恢复和关闭窗口设置；实际触发一条普通 VALARM 与一条比赛提醒，验证刷新/重启不重复及权限状态可解释。
- **真实订阅与常驻：** 使用专门的验收订阅验证添加、200/304 刷新、离线保留缓存和删除；运行跨本地午夜，完成一次休眠恢复；在默认与最小窗口、明暗主题下检查日期、详情与操作入口。不得写入或删除用户现有日历。
- **证据：** 实机记录写明构建版本、日期、环境、输入、预期和实际结果。通知 mock、HTTP 替身和编译通过只证明各自边界；无法执行的项目标为“未验收”，不计为通过。

### 验收

- [ ] 网格外选中日期的完整 Inspector 仍正确，来源开关和改选即时生效。
- [ ] 跨午夜/月末/年末后今天标记正确；回到今天与窗口恢复读取当前本机日期。
- [ ] 下载、解析、标准化、落库任一阶段删除订阅，最终及重启后均无来源、原始事件或增强残留。
- [ ] 删除后重加同地址时，旧刷新结果不能写入新来源。
- [ ] 在途 HTTP 可主动取消；主动取消不清缓存、不伪报失败、不触发失败重试，其他来源继续工作。
- [ ] 现有 ICS、时区、recurrence、Matcher、提醒去重、来源持久化及脱敏回归保持通过。
- [ ] 日期校正与刷新修复不增加高频轮询；大数据分片与空闲资源有复测记录。
- [ ] 实际打包图标的来源和分发授权有证据，文档参考图待处理项已解决或明确阻断公开分发。
- [ ] 生成与修复提交对应的 Windows RC，并完成上述安装、升级、卸载、托盘、通知、真实订阅、跨天与休眠恢复验收。
- [ ] README、发布/UI/资产记录及 Epic 与实际结果一致；参考视觉降级仍如实标注。

## Out of Scope

- Google Calendar/Outlook 双向同步、完整 CalDAV、移动端、账号系统、Dashboard、AI 识别和其他联赛。
- 更换 JSON 存储为 SQLite、把现有分片架构搬到 Worker 或后台服务，除非有本范围内的已验证必要性。
- 自动更新、应用退出后的提醒、专门离线 WebView2 安装包。
- 队徽/联赛 Logo 资源包、节日节气或球场照片接入，以及对参考图的全面重做。
- 购买签名证书或素材授权、输入用户凭据、公开发布安装包；遇到必须由用户完成的授权或费用操作，保留具体未完成项。
- 在编写本规格时实施修复、伪造实机结果或提前关闭 Epic。

## Further Notes

目标：补齐 V0.1 日历可靠性与发布门槛；这是一张收尾规格，可按内部阶段推进，不把关闭的旧工单重新计为未实现。

范围：三项缺陷、网络取消与操作失效隔离、当前 RC 和验收证据、资产待处理项、发布状态同步。资源视觉维持原定范围。

依赖：SC-005、SC-007、SC-017、SC-018、SC-019、SC-020、SC-021、SC-022、SC-024（现均已关闭）。执行顺序为日期/详情与删除修复 → HTTP 取消及回归 → 资产处理 → 固定 RC 与实机验收 → 文档/Epic 收尾。

Spec：App Spec §2、CAL-001–003、SRC-002–004、§11–14、§17–18、§20–21；UI Spec 的 Inspector 与月视图验收规则。

复核基准为 `f22cf8d`：83 文件/965 前端用例、19 Rust 用例、构建和静态检查通过，但额外三项复现均失败。不能以已有测试全绿替代本规格验收。

公开分发授权与原生系统验收可能需要人工参与；`ready-for-agent` 表示规格可执行，不表示外部授权或全部 Windows 验收已经完成。
