# SC-025 工单拆分草案

来源：[SC-025 规格 #27](https://github.com/q956085398-netizen/semantic-calendar/issues/27)。状态：待用户确认拆分，尚未创建子工单；SC-026–SC-032 为拟用编号，发布前再次检查编号占用。

每张工单交付一个可独立验证的用户行为或发布结果，不按前端、后端、测试分别拆单。已有测试与存储边界足够，不单开无用户结果的宽泛重构工单；必要的内部整理放在对应行为切片开头，保持既有链路可用。

## 拆分与依赖

1. **SC-026 [P1][Calendar] 切月后保留选中日期的完整 Inspector**。无阻塞。交付选择日期与视图月份分离后的完整详情。
2. **SC-027 [P1][Calendar] 常驻跨天与恢复窗口时校正今天状态**。无阻塞。交付当前日期标记、恢复校正与真正的回到今天。
3. **SC-028 [P1][WebCal] 删除订阅后隔离晚到刷新与同地址旧结果**。无阻塞。交付下载、解析、标准化与落库期间都可靠的删除，以及删除后同地址重加隔离。
4. **SC-029 [P1][WebCal] 取消在途订阅请求并保留缓存和正常状态**。阻塞：SC-028。复用其刷新操作身份与失效规则，将主动取消贯穿前端、IPC、Rust HTTP 和调度状态。
5. **SC-030 [P1][Release] 完成分发资产授权记录并处理来源不明参考图**。无阻塞。交付可证明来源的实际打包资产与处理完毕的参考素材。
6. **SC-031 [P1][Release] 构建当前 Windows RC 并验收安装和系统集成**。阻塞：SC-026、SC-027、SC-029、SC-030。生成固定版本产物，完成安装、升级、卸载、托盘和实际通知验收；SC-028 已被 SC-029 传递覆盖。
7. **SC-032 [P1][QA] 验收当前 RC 的真实订阅与常驻行为并同步发布证据**。阻塞：SC-031。基于同一安装产物验证真实订阅、离线、跨午夜、休眠恢复、性能和界面，收拢 V0.1 的最终证据。

可立即开始：SC-026、SC-027、SC-028、SC-030。SC-029 依赖 SC-028 是因为二者共享刷新生命周期契约，避免各自发明互不一致的取消和删除身份。SC-031 必须等行为修复与资产处理完成，才能冻结被验收产物；SC-032 必须使用这份已安装 RC，而不是开发版或旧安装包。

## SC-026 [P1][Calendar] 切月后保留选中日期的完整 Inspector

### Parent

规格 #27；V0.1 Epic #1。发布时关联到规格下，保留 Epic 引用，不改动或关闭父工单。

### What to build

用户选中日期后，可以浏览其他月份而继续查看该日完整详情。Inspector 与选中日期绑定，复用 occurrence 展开、日级语义和来源开关规则；大数据查询保持可响应，晚到结果不会覆盖新选择。

### Acceptance criteria

- [ ] 选中含普通事件、比赛、农历和假期的日期，跨两个月后右栏仍显示原日期和完整可用详情，返回原月无差异。
- [ ] 重复事件正确展开为所选日期的 occurrence；普通空白日期保持原有留白，不凭空填充事件。
- [ ] 选中日期在网格外时，来源开关和重新选择仍立即生效。
- [ ] 快速切月、快速改选和大数据分片读取不发布旧日期或半份事件，整理状态可解释。
- [ ] 真实 App 操作的集成回归覆盖已复现的“日期保留但农历消失”场景，现有导航与语义测试保持通过。
- [ ] 不在 UI 新增领域识别规则，不更换存储或扩展当前视觉资源范围；相关文档与新行为一致。

### Blocked by

无，可立即开始。

### 范围、依赖与 Spec

对应 SC-025 用户故事 1–6，CAL-003、中国日历与赛事 Inspector。既有 SC-005、SC-008、SC-010–SC-016、SC-018 已完成，不作为新的阻塞。

## SC-027 [P1][Calendar] 常驻跨天与恢复窗口时校正今天状态

### Parent

规格 #27；V0.1 Epic #1。

### What to build

让长期运行的日历以当前本机日期显示今天状态；跨午夜、恢复窗口和点击今天时更新。更新标记不打断正在浏览的月份或选择，点击今天才将视图与选择归位。

### Acceptance criteria

- [ ] 普通午夜、月末、年末、闰日后，今天标记采用新的本机日期。
- [ ] 点击“今天”即使没有重启，也返回当前日期并选中该日；启动日不再被固定成永久今天。
- [ ] 托盘恢复、休眠恢复或系统日期调整后，恢复/交互触发能重新校正日期。
- [ ] 仅日期校正不自动切月或重选日期，保留用户当前阅读位置。
- [ ] 假时钟与现有生命周期测试覆盖日期推进及恢复，提醒计划跨天重建仍正确。
- [ ] 复用低频跨天和生命周期触发，不增加高频轮询；监听与调度清理完整，相关文档同步。

### Blocked by

无，可立即开始。与 SC-026 涉及相邻状态，但不存在必须先完成对方的行为依赖。

### 范围、依赖与 Spec

对应 SC-025 用户故事 7–12，CAL-001–002、长期常驻和后台行为。系统缩放和默认窗口布局不在本单重做。

## SC-028 [P1][WebCal] 删除订阅后隔离晚到刷新与同地址旧结果

### Parent

规格 #27；V0.1 Epic #1。

### What to build

用户可在刷新任何阶段删除订阅。删除后来源、原始事件、增强结果都不会被晚到操作复活；立即重新添加同地址只接受新操作结果。采用运行期操作身份与受控提交规则，不把“检查一次来源存在”当作全程保护。

### Acceptance criteria

- [ ] 在下载、解析、标准化及分片落库任一阶段删除，全部在途工作结束后来源、事件、增强结果均为空。
- [ ] 上述最终状态落盘再读回后仍成立，260 条复现及 10,000 条分片数据均无孤立记录。
- [ ] 删除后立刻重加相同 URL，旧请求不能覆盖新来源、缓存、启用状态或错误状态；旧操作清理不会注销新操作。
- [ ] 多来源并发时删除一源不影响其他来源；同一来源普通并发刷新仍避免重复下载。
- [ ] App 删除操作与真实存储边界的行为测试通过，不只验证内部来源查询次数。
- [ ] 已有网络失败缓存、UID 去重、增强与分片性能契约保持有效，删除不泄露敏感 URL 或事件正文。
- [ ] 交付完整结果失效与提交隔离；本单不要求真正停止 Rust HTTP，网络资源释放由 SC-029 补齐。

### Blocked by

无，可立即开始。

### 范围、依赖与 Spec

对应 SC-025 用户故事 14–16、19–21，SRC 与来源删除级联规则；运行期身份不计划持久化 schema 变更。

## SC-029 [P1][WebCal] 取消在途订阅请求并保留缓存和正常状态

### Parent

规格 #27；V0.1 Epic #1。

### What to build

删除订阅、停用其在途后台刷新或退出应用时，真正结束相应 HTTP 等待/读取，同时沿用 SC-028 的结果隔离。取消单独表达，不伪报网络失败、不删除缓存、不推动成功时间或失败重试。隐藏到托盘仍保持常驻调度。

### Acceptance criteria

- [ ] 本地延迟响应及缓慢正文服务证明取消可结束等待和读取，不必等到总超时。
- [ ] 删除、停用在途后台刷新及退出生命周期均贯通取消；仅隐藏到托盘不终止正常常驻任务。
- [ ] 停用保留来源、事件和增强数据，后续后台刷新停止；显式手动刷新保持已有交互语义。
- [ ] 主动取消不推进上次成功时间、不覆盖正常错误信息、不触发失败重试，缓存可继续浏览。
- [ ] 多来源并发与同地址重加场景中，只取消目标操作，旧取消或清理不影响新请求。
- [ ] 前端、桌面 IPC 和 Rust 请求处理的取消身份一致，完成/失败/取消后的注册与监听均被清理。
- [ ] 保留连接/总超时、正文上限、条件 GET、304、真正失败重试、凭据脱敏与 SC-028 删除回归。
- [ ] 用户行为集成测试与现有本地 HTTP 测试边界有真实取消覆盖；文档明确新取消结果与缓存策略。

### Blocked by

- SC-028：提供刷新操作身份、晚到结果失效与提交规则。

### 范围、依赖与 Spec

对应 SC-025 用户故事 13、17–22，后台网络任务可取消、错误降级和隐私。无需新增常驻进程或“取消全部来源”的全局副作用。

## SC-030 [P1][Release] 完成分发资产授权记录并处理来源不明参考图

### Parent

规格 #27；V0.1 Epic #1。

### What to build

让实际打包资产有可核对的来源与分发授权，处理文档参考图来源未记录的问题。无法确认授权的打包素材使用来源可证明的自有替代素材；不会因为素材处理而引入新视觉范围。

### Acceptance criteria

- [ ] 新增生成图标逐项登记来源、用途和可核验分发授权证据；来源记录不依赖未提交的本地 kit 才能理解。
- [ ] 授权无法确认的打包图标已被自有替代素材替换，构建和相关界面使用实际确认后的素材。
- [ ] 来源不明参考图已补足来源/授权或从分发范围移除，关联引用同步，不留断链或虚假许可陈述。
- [ ] 实际打包内容与资产清单一致，资产守卫、文档引用检查及构建通过；必要时检查真实渲染的图标加载。
- [ ] 队徽、联赛 Logo 和照片继续按已接受的 fallback 范围处理，照片项部分通过的口径保留。
- [ ] 不购买授权/证书、不支付费用、不公开发布；不可由 agent 独立取得的授权事实明确报告，不猜测授权有效。

### Blocked by

无，可立即开始。

### 范围、依赖与 Spec

对应 SC-025 用户故事 28–29、发布资产审查；SC-022 已接受的默认视觉范围维持不变。

## SC-031 [P1][Release] 构建当前 Windows RC 并验收安装和系统集成

### Parent

规格 #27；V0.1 Epic #1。

### What to build

从已修复、资产处理完毕的确定提交生成可安装的 Windows RC，实际验证安装、升级、卸载、托盘和系统通知，使产物与验收证据对应同一代码版本。

### Acceptance criteria

- [ ] 当前提交的核心测试、静态检查和构建通过；记录提交标识、构建时间、安装包校验值及验收环境。
- [ ] 当前 RC 的安装、启动、应用名称/版本、安装向导、卸载逐项有实际记录；不能套用 9 月 25 日旧包结果。
- [ ] 在隔离的验收数据上升级保留来源、事件、设置和提醒去重状态；卸载保留用户数据并清理安装内容。
- [ ] 实际操作托盘隐藏、恢复、退出、关闭行为设置及单实例恢复，结果符合界面承诺。
- [ ] 已安装应用实际触发普通 VALARM 与比赛提醒，验证刷新/重启去重及权限状态可解释；mock 结果不算系统通知通过。
- [ ] 生产代码或打包资产变更后，重新生成产物并复验受影响项，交给 SC-032 的是固定验收版本。
- [ ] 保存安装与系统集成证据、已知限制和未验收项；无法操作的原生项目如实标记，不能关闭工单为通过。
- [ ] 不修改用户现有日历、不公开发布、不购买签名证书；对需要用户执行的步骤提供具体清单。

### Blocked by

- SC-026：日期详情修复。
- SC-027：运行期今天状态修复。
- SC-029：完整订阅取消链路，传递包含 SC-028。
- SC-030：实际打包资产处理完成。

### 范围、依赖与 Spec

对应 SC-025 用户故事 23–27，Windows 发布门槛、本地通知、托盘与升级策略。时间行为与远程网络长测交给 SC-032。

## SC-032 [P1][QA] 验收当前 RC 的真实订阅与常驻行为并同步发布证据

### Parent

规格 #27；V0.1 Epic #1。

### What to build

在 SC-031 的同一安装产物上，完成真实订阅、离线缓存、跨午夜、休眠恢复、大日历性能及明暗/最小窗口检查。将各项已完成、接受降级和未验证状态同步到发布资料，形成可复查的 V0.1 收尾结论。

### Acceptance criteria

- [ ] 专门验收订阅实际完成添加、200/304 更新、禁用、删除与离线缓存验证，不访问或改写用户现有订阅。
- [ ] 已安装 RC 运行跨本地午夜并完成一次休眠恢复，今天标记、回到今天、原选中日期详情和提醒行为符合规格。
- [ ] 默认与最小窗口、明暗主题实际检查切月详情和操作入口，记录画面与环境；不以 jsdom 证明真实布局通过。
- [ ] 用既有固定 1,000/10,000 事件负载复测受影响读取/刷新路径与可见/托盘隐藏空闲资源，记录实际数字和相对基线变化。
- [ ] README、发布、资产及 UI 验收资料明确对应当前 RC；已接受视觉降级仍如实记录，不以图片组件能力声称默认参考视觉完成。
- [ ] 汇总 SC-025 全部验收项到证据清单，纳入 SC-023/024 与本轮工作状态；保留失败/未验收项并给出下一步，不虚构完成。
- [ ] 为父规格及 V0.1 Epic 提供逐项状态对照和建议更新内容；本轮拆单发布不修改或关闭任何父工单。
- [ ] 本规格所有发布门槛具备证据后才报告收尾完成；对原生操作、授权或环境不足明确说明缺口。

### Blocked by

- SC-031：提供确定版本、已实际安装且通过系统集成验收的 RC。

### 范围、依赖与 Spec

对应 SC-025 用户故事 20、22、29–30，以及十二项成功标准的证据收尾。复用现有性能与人工验收方法，不引入截图回归系统或扩大产品范围。

## 发布规则

- 用户确认粒度、依赖和合并/拆分选择后，才发布这七张子工单。
- 发布前重新检查最大 SC 编号；按依赖顺序发布，每张一条 GitHub Issue。
- 每张使用中文正文，保留 Parent、目标/范围、可验证验收、依赖与 Spec，对应状态标签为 `ready-for-agent`，分类按 `bug` 或 `enhancement`。
- 优先使用 GitHub 原生子工单和 blocking links；不可用时在正文显式列出真实工单号，核对所有依赖。
- 维护仓库任务清单和 README 的待实现状态。不修改、关闭 SC-025 或 Epic #1。
